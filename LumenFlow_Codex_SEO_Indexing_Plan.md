# Lumen&Flow SEO Indexing Implementation Plan

## Purpose

Prepare the currently deployed Lumen&Flow website for safe Google Search Console submission without allowing unfinished service and case-study pages to enter Google's index.

This task is limited to codebase changes. Cloudflare redirects, Search Console setup, Google Analytics, and Google Tag Manager configuration are outside this implementation scope.

## Repository Context

- Repository: `Lumen-Flow/lumenflow.co`
- Framework: Next.js App Router
- Canonical production domain: `https://lumenandflow.co`
- Production deployment: Coolify behind Cloudflare
- Current completed public page: Homepage
- Current unfinished public routes:
  - `/technology`
  - `/marketing`
  - `/creatives`
  - `/case-studies`
  - `/case-studies/apidenna`
  - `/case-studies/battery-house`

The unfinished routes currently contain placeholder content and must not be submitted for indexing.

---

## Objectives

1. Keep the homepage indexable.
2. Restrict the XML sitemap to the completed homepage.
3. Add `noindex, follow` metadata to every unfinished route.
4. Preserve canonical URLs for all routes.
5. Keep crawlers able to access unfinished routes so they can read the `noindex` directive.
6. Avoid changing the existing `robots.txt` implementation.
7. Ensure the project passes linting, type checking, formatting, and production build checks.
8. Document how to re-enable indexing when each page is completed.

---

## Non-Goals

Do not implement any of the following in this task:

- Cloudflare redirect rules
- HTTP-to-HTTPS status-code changes
- Google Search Console verification
- Google Analytics 4
- Google Tag Manager
- Conversion tracking
- Organization or WebSite JSON-LD
- Open Graph image generation
- Content rewrites
- Page redesigns
- Removal of existing routes
- Changes to Cloudflare-managed crawler controls
- `llms.txt`
- Blog or content management functionality

These should be handled in separate tasks.

# Implementation Tasks

## Task 1 — Restrict the Sitemap to the Homepage

### File

```text
src/app/sitemap.ts
```

### Current Problem

The sitemap currently includes unfinished service pages, the case-study index, and unfinished individual case-study pages.

Search engines should only receive canonical URLs that are ready to appear in search results.

### Required Change

Replace the current static and case-study route generation with a homepage-only sitemap.

Use:

```ts
import type { MetadataRoute } from "next";

import { siteConfig } from "@/content/site";

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: siteConfig.url,
    },
  ];
}
```

### Requirements

- Use `siteConfig.url` as the sitemap URL source.
- Do not hardcode the production domain in this file.
- Do not include placeholder routes.
- Do not add a generated `lastModified` value on every build.
- Do not add `changeFrequency` or `priority` unless there is a justified project-wide sitemap policy.
- Preserve the standard Next.js metadata route approach.

### Expected Production Output

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://lumenandflow.co/</loc>
  </url>
</urlset>
```

Minor XML formatting differences generated by Next.js are acceptable.

## Task 6 — Noindex Dynamic Case-Study Pages

### File

```text
src/app/case-studies/[slug]/page.tsx
```

### Current Behaviour

`generateMetadata()` currently returns a title and canonical URL for each valid case-study slug.

### Required Change

Add a robots directive to the metadata returned for valid case studies:

```ts
return {
  title: caseStudy.name,
  alternates: {
    canonical: `/case-studies/${caseStudy.slug}`,
  },
  robots: {
    index: false,
    follow: true,
  },
};
```

### Requirements

- Preserve `generateStaticParams()`.
- Preserve the current `notFound()` behaviour.
- Preserve dynamic titles.
- Preserve dynamic canonical URLs.
- Apply the same noindex state to all current and newly added case studies until the route is intentionally made indexable.
- Do not add individual case-study routes to the sitemap in this task.

# Files That Must Not Be Changed

## `src/app/robots.ts`

The existing implementation already:

- Allows crawling
- References the sitemap
- Produces a valid Next.js metadata route

Do not add `Disallow` rules for the unfinished pages. Search engines must be able to crawl those pages to read their `noindex` metadata.

## `src/content/site.ts`

The production URL is already:

```ts
url: "https://lumenandflow.co"
```

Do not change the canonical hostname.

## `src/app/layout.tsx`

The root metadata already uses `siteConfig.url` as `metadataBase` and provides global title, description, canonical, Open Graph, and Twitter metadata.

Do not modify it as part of this narrowly scoped indexing task unless the existing implementation fails type checking or build validation.

## Cloudflare-Managed `robots.txt` Content

The crawler-specific block visible in production is inserted by Cloudflare. It is not generated by this repository.

Do not attempt to reproduce or remove that managed block in application code.

# Re-Enabling a Page for Indexing

When a page is genuinely complete, use this sequence.

## For a Static Page

Example: `/technology`

1. Remove:

```ts
robots: {
  index: false,
  follow: true,
},
```

2. Confirm the page has:
   - A unique title
   - A unique meta description
   - One clear H1
   - Substantial visible content
   - Relevant internal links
   - A valid self-referencing canonical URL
   - No placeholder copy

3. Add the route back to `src/app/sitemap.ts`.

4. Run all quality checks.

5. Deploy through Coolify.

6. Validate production metadata.

7. Inspect and request indexing in Google Search Console.

## For Case Studies

Do not make the entire dynamic case-study template indexable until every generated case study is publication-ready.

A safer future design is to add a publication/indexing property to the case-study data model, for example:

```ts
{
  slug: "apidenna",
  name: "Apidenna",
  seo: {
    indexable: true,
  },
}
```

Then use that property consistently in:

- `generateMetadata()`
- `sitemap.ts`
- Navigation or listing visibility where appropriate

Do not implement that data-model change in this task unless explicitly requested.
